# Desafio — Semana 36 — Portfólio Final e Posicionamento de Carreira

## Contexto

Você chegou à semana 36. Nos últimos 9 meses, construiu expertise técnica que poucos
desenvolvedores brasileiros têm: protocolo ISO 8583 do zero ao clearing, EMV, PCI-DSS,
antifraude, performance engineering a 5.000 TPS, comunicação técnica e estratégia de carreira.

O desafio final não é técnico — é de posicionamento. O mercado não vai bater na sua
porta só porque você sabe o conteúdo. Você precisa ser encontrável, compreensível
e confiável para as pessoas certas.

Este desafio tem três partes que você levará para fora do curso.

## O Problema

Você tem o conhecimento. Falta a embalagem.

Um recrutador de Staff Engineer numa fintech leva 15 segundos lendo seu LinkedIn.
Um CTO decide em 2 minutos se vai querer conversar com você. Um engenheiro sênior
decide em 30 segundos se seu repositório no GitHub vale a pena clonar.

Você precisa que esses 15 segundos, 2 minutos e 30 segundos trabalhem a seu favor.

## Missão

### Parte 1 — GitHub: O Repositório que Conta uma História

Audite o seu `payment-switch-lab` (ou o repositório principal do curso) e avalie
cada item abaixo. Para os que estiverem ausentes ou insuficientes, escreva o conteúdo:

**README.md — checklist de qualidade:**
- [ ] Título e tagline (o que é, em 1 frase)
- [ ] Por que este projeto existe (motivação, não lista de features)
- [ ] Diagrama de arquitetura (pode ser ASCII art ou Mermaid)
- [ ] Como rodar localmente (pré-requisitos + comandos exatos)
- [ ] Funcionalidades implementadas (com status: completo / em progresso)
- [ ] Decisões de design (link para ADRs ou seção inline)
- [ ] Tecnologias usadas e por quê (não só o nome — o motivo)
- [ ] O que você aprendeu construindo isso (diferencial humano)

Escreva o README completo que o repositório deveria ter. Mínimo 400 palavras.

**Estrutura do repositório:**
Liste a estrutura de diretórios ideal para o `payment-switch-lab` que comunique
clareza e organização profissional para alguém que vê o repositório pela primeira vez.

### Parte 2 — LinkedIn: O Perfil que Abre Portas

Escreva o conteúdo completo para as seções mais importantes do seu LinkedIn:

**Headline (máximo 220 caracteres):**
Não use "Desenvolvedor Java Sênior". Use sua especialidade específica.
Escreva 3 versões e escolha a melhor.

**Sobre (máximo 2.600 caracteres):**
Use a estrutura da teoria (narrativa profissional completa). Deve incluir:
- Primeira frase que captura atenção
- O que você constrói e para qual resultado
- Seu diferencial no ecossistema de pagamentos brasileiro
- O que você está buscando (sem parecer desesperado)
- Call to action (como entrar em contato)

**Experiência — descrição da posição atual/mais recente:**
Escreva a descrição de 1 posição usando bullets orientados a impacto,
não a responsabilidades. Formato: verbo de ação + o que fez + resultado mensurável.

Exemplo do formato correto:
```
✓ Implementei switch ISO 8583 com jPOS processando 2.400 TPS com P95 < 80ms
✓ Reduzi falsos positivos do antifraude em 40% calibrando modelo com Redis velocity rules
✗ "Responsável pelo desenvolvimento de sistemas de pagamento" (sem impacto)
```

### Parte 3 — Plano de 90 Dias Pós-Curso

O curso termina. O que você faz na próxima segunda-feira?

Crie um plano semanal para os próximos 90 dias com ações específicas e mensuráveis.
Organize por semana (não por mês) para ser executável:

```
Semana 1:
  [ ] Publicar repositório payment-switch-lab com README revisado
  [ ] Atualizar headline e "Sobre" do LinkedIn
  [ ] Identificar 1 issue no jPOS para contribuir

Semana 2:
  [ ] [Ação específica]
  [ ] [Ação específica]

... (continue até a semana 12)
```

Regras do plano:
- Cada semana deve ter no máximo 3 ações (foco)
- Cada ação deve ser binária: feito ou não feito (não "continuar trabalhando em X")
- As ações das semanas 9-12 devem ser consequência das semanas 1-8

Ao final, escreva 1 parágrafo: como você saberá, ao final dos 90 dias, que o plano
funcionou? Que evidência concreta você terá?

## Critérios de Avaliação

- [ ] README escrito com as 8 seções do checklist, mínimo 400 palavras (Parte 1)
- [ ] Estrutura de diretórios proposta reflete organização profissional (Parte 1)
- [ ] 3 versões de headline escritas, com escolha justificada (Parte 2)
- [ ] Seção "Sobre" com todas as partes estruturais e call to action (Parte 2)
- [ ] Bullets de experiência orientados a impacto com métricas (Parte 2)
- [ ] Plano de 90 dias com ações binárias e progressão lógica (Parte 3)
- [ ] Critério de sucesso do plano com evidência concreta e mensurável (Parte 3)

## Dicas

- O README que conta uma história é diferente do README que lista funcionalidades
- "Por que este projeto existe" é a seção mais importante — é o que separa um projeto
  de portfólio de um projeto de aprendizado
- No LinkedIn, recrutadores leem o headline antes de clicar no perfil — invista nele
- Bullets de experiência com números (TPS, latência, %) são 3x mais memoráveis que sem
- Um plano de 90 dias com 3 ações/semana é executável; 10 ações/semana não é
- A evidência de sucesso dos 90 dias deve ser externa: alguém fez contato, PR aceito,
  convite para evento — não apenas "me sinto mais confiante"
